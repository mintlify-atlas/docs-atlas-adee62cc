title: "Disk and Partition Configuration"
description: "Configure disks, partitions, and artifacts for Azure Linux images"
---

The `Disks` section of the image configuration defines the physical disk layout, partition structure, and output artifacts for your Azure Linux image.

## Disk Configuration

Each disk entry defines a complete disk layout:

<ParamField path="PartitionTableType" type="string" required>
  Partition table type: `gpt` or `mbr`
</ParamField>

<ParamField path="MaxSize" type="number" required>
  Maximum disk size in megabytes (for virtual disks)
</ParamField>

<ParamField path="Artifacts" type="array">
  Array of artifact definitions specifying output image format
</ParamField>

<ParamField path="Partitions" type="array">
  Array of partition definitions. Omit for rootfs-only images
</ParamField>

<ParamField path="TargetDisk" type="object">
  Required for unattended ISO installer. Defines physical disk for installation
</ParamField>

### Example Disk Configuration

```json
{
    "Disks": [
        {
            "PartitionTableType": "gpt",
            "MaxSize": 4096,
            "Artifacts": [
                {
                    "Name": "core",
                    "Type": "vhdx"
                }
            ],
            "Partitions": [...]
        }
    ]
}
```

## Artifacts

Artifacts define the output image format and compression:

<ParamField path="Name" type="string" required>
  Base name for the output artifact
</ParamField>

<ParamField path="Type" type="string">
  Image type: `vhd`, `vhdx`, `iso`, `qcow2`, etc. Default: raw disk image
</ParamField>

<ParamField path="Compression" type="string">
  Compression format: `tar.gz`, `gz`, `xz`, etc.
</ParamField>

### VHDX Disk Image

```json
"Artifacts": [
    {
        "Name": "otherName",
        "Type": "vhdx"
    }
]
```

### Compressed Rootfs

```json
"Artifacts": [
    {
        "Name": "core",
        "Compression": "tar.gz"
    }
]
```

<Note>
Rootfs artifacts (with compression like `tar.gz`) do not support partitions.
</Note>

## Partition Configuration

Partitions define the layout of each disk:

<ParamField path="ID" type="string" required>
  Unique identifier for the partition
</ParamField>

<ParamField path="Name" type="string">
  Partition label. Required when using `partlabel` mount identifier
</ParamField>

<ParamField path="Start" type="number" required>
  Start offset in megabytes from beginning of disk
</ParamField>

<ParamField path="End" type="number" required>
  End offset in megabytes. Set to `0` to use remaining space
</ParamField>

<ParamField path="FsType" type="string" required>
  Filesystem type: `fat32`, `fat16`, `vfat`, `ext2`, `ext3`, `ext4`, `xfs`, `linux-swap`
</ParamField>

<ParamField path="Flags" type="array">
  Special partition flags for boot handling
</ParamField>

<ParamField path="Type" type="string">
  Partition type using friendly name (alternative to TypeUUID)
</ParamField>

<ParamField path="TypeUUID" type="string">
  Partition type UUID (alternative to Type)
</ParamField>

### EFI Boot + Root Partition

```json
"Partitions": [
    {
        "ID": "boot",
        "Flags": ["esp", "boot"],
        "Start": 1,
        "End": 9,
        "FsType": "fat32"
    },
    {
        "ID": "rootfs",
        "Start": 9,
        "End": 0,
        "FsType": "ext4",
        "Type": "linux-root-amd64"
    }
]
```

### Legacy GRUB Boot + Root Partition

```json
"Partitions": [
    {
        "ID": "boot",
        "Flags": ["grub"],
        "Start": 1,
        "End": 9,
        "FsType": "fat32"
    },
    {
        "ID": "rootfs",
        "Start": 9,
        "End": 0,
        "FsType": "ext4"
    }
]
```

### Three-Partition Layout (EFI + Boot + Root)

```json
"Partitions": [
    {
        "ID": "efi",
        "Flags": ["esp", "boot"],
        "Start": 1,
        "End": 65,
        "FsType": "fat32"
    },
    {
        "ID": "boot",
        "Start": 65,
        "End": 565,
        "FsType": "ext4"
    },
    {
        "ID": "rootfs",
        "Name": "rootfs",
        "Start": 565,
        "End": 0,
        "FsType": "ext4"
    }
]
```

## Partition Flags

Special flags control boot and partition handling:

<ResponseField name="esp" type="flag">
  UEFI ESP (EFI System Partition)
</ResponseField>

<ResponseField name="boot" type="flag">
  Boot partition
</ResponseField>

<ResponseField name="grub" type="flag">
  GRUB boot partition
</ResponseField>

<ResponseField name="bios_grub" type="flag">
  BIOS GRUB boot partition
</ResponseField>

<ResponseField name="dmroot" type="flag">
  Device mapper root device (for encryption)
</ResponseField>

### Using Partition Types

```json
{
    "ID": "rootfs",
    "Start": 9,
    "End": 0,
    "FsType": "ext4",
    "Type": "linux-root-amd64"
}
```

## Target Disk (ISO Installer)

Required for unattended ISO installers to specify installation target:

```json
{
    "TargetDisk": {
        "Type": "path",
        "Value": "/dev/sda"
    }
}
```

## Common Configurations

### Virtual Machine (VHDX)

```json
{
    "Disks": [
        {
            "PartitionTableType": "gpt",
            "MaxSize": 4096,
            "Artifacts": [
                {
                    "Name": "core",
                    "Type": "vhdx"
                }
            ],
            "Partitions": [
                {
                    "ID": "boot",
                    "Flags": ["esp", "boot"],
                    "Start": 1,
                    "End": 9,
                    "FsType": "fat32"
                },
                {
                    "ID": "rootfs",
                    "Start": 9,
                    "End": 0,
                    "FsType": "ext4"
                }
            ]
        }
    ]
}
```

### Container Rootfs

```json
{
    "Disks": [
        {
            "Artifacts": [
                {
                    "Name": "core",
                    "Compression": "tar.gz"
                }
            ]
        }
    ]
}
```

<Note>
Container rootfs images do not include partitions.
</Note>
